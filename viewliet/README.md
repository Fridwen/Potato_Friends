# Viewliet

선택 평면도 이미지 최대 1장, 원룸 사진 1~6장과 전용면적을 입력하면 추정 평면도와 3D 실내 둘러보기를 생성하는 해커톤 웹앱입니다. Next.js App Router + TypeScript + Three.js + OpenAI Responses API를 사용합니다.

## 실행

Node.js 22 이상과 pnpm을 권장합니다.

```sh
pnpm install
cp .env.example .env.local
# .env.local의 OPENAI_API_KEY에 본인의 API 키 설정
pnpm dev
```

http://localhost:3000 에 접속합니다. API 키 없이도 기본 화면의 20㎡ 예시 JSON 공간은 바로 사용할 수 있습니다. 키를 설정한 뒤 서버를 재시작해야 합니다. 비밀 키는 서버의 `OPENAI_API_KEY` 환경변수로만 읽으며 브라우저에 전달하지 않습니다. 로그인이나 키 입력 UI는 없습니다.

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm start
```

개발 서버는 파일 감시 한도가 낮은 환경을 위해 polling을 사용합니다. 배포용 실행은 `pnpm build && pnpm start`입니다.

## 구현한 기능

- 사진 1~6장 추가·삭제·드래그 업로드, 원본 미리보기. JPG/PNG/WebP, 각 8MB 이하.
- 전용면적 8~80㎡ 입력. 첫 버전은 직사각형 원룸 한 세대만 지원.
- 예시 JSON 체험. 업로드 결과와 예시를 명확히 구분.
- `/api/analyze`에서 OpenAI `gpt-6-astra` (추론 low (Light))에 여러 사진을 한 요청으로 전달.
- Responses API의 strict JSON Schema Structured Outputs + Zod 런타임 검증. 실행 코드 생성/실행 없음.
- 사진 근거가 있는 구조와 가구만 최종 JSON에 포함. 방 하나와 사진에서 확인되는 화장실만 표시하고, 주방·현관은 별도 방으로 만들지 않음. 확인되지 않은 연결은 생성하지 않음.
- 총 면적을 외곽에 한 번 적용, 가로세로 비율 추정, 직사각형 차집합으로 겹치는 공간 제거. 미확인 영역을 새 공간으로 채우지 않음.
- 음수/비정상 크기 보정, NaN/Infinity 거부, 90도 단위 방향 보정 및 회전된 가구 외곽 경계 검증.
- AI의 물체 identity와 근접 동일 종류 물체 검사를 조합한 중복 억제.
- 문/창문 위치와 크기 검증. 3D 벽에는 실제 개구부를 생성.
- 동일한 최종 `Space` 객체를 SVG 평면도와 Three.js 모델에서 사용. 최종 JSON 다운로드.
- 전체 공간 모형과 360도 실내 시선 모드, Pointer Events 기반 마우스/터치 드래그, 공간별 시점 이동, 시선 초기화.
- 전체 화면 API + API 미지원 시 CSS 확장 화면, WebGL 생성 실패/컨텍스트 손실 시 평면도 대체 표시.
- 주요 가정, 항목별 관찰/추정과 원본 사진 번호, 보정 내역, 추정 안내 상시 표시. 전체 화면에도 안내 포함.
- 업로드 실제 파일 시그니처 검사, 스트리밍 본문 크기 제한, 중복 요청 제한, 타임아웃·키 누락·잘못된 응답·AI 거절 안내.
- 사진은 앱 메모리에서 처리하고 DB/서버 파일로 저장하지 않음. OpenAI 요청은 `store:false` 사용. OpenAI 측 데이터 처리는 해당 API 계정 정책을 따름.

## 데이터 모델 / 좌표

`lib/space.ts`의 `SpaceSchema`가 AI 응답 계약입니다. `lib/example.ts`가 원본 예시이며 `public/example-space.json`은 보정된 최종 예시입니다.

- 단위: m. x는 동/오른쪽, z는 남/아래, y는 높이. 원점은 실내 북서쪽.
- shell: 전체 외곽 width/depth/height. 면적은 width × depth로 계산.
- zones: x/z는 사각형 좌상단. 서로 겹치지 않는 관찰 영역. 이름은 방/화장실이며 전체 전용면적을 덮을 필요 없음. 화장실을 감싸는 방의 면적 계산 조각들은 displayZones로 하나의 이름/이동 버튼으로 표시.
- partitions: x/z 시작점에서 axis x 또는 z 방향으로 length만큼 연장.
- openings: wallId는 north/south/east/west 또는 칸막이 ID. offset은 벽 시작점부터 거리, sill은 바닥부터 개구부 아래 높이.
- furniture: x/z는 중심, width/depth는 로컬 크기. rotation은 평면도 기준 시계 방향 0/90/180/270도.
- evidence: observed/inferred, 1부터 시작하는 사진 번호, 설명. 물체 관찰은 실제 치수를 측정했다는 뜻이 아님.
- connections: 공간 ID 간 연결 근거. 사진으로 확인된 연결만 포함. 관찰되지 않은 연결은 형상을 만들지 않고 설명에만 남김. 이동 버튼은 실제 보행 경로가 아닌 가상 시점 이동.
- assumptions / corrections: 주요 추정과 프로그램 보정 내역.

## 검증 결과

27개 Node 테스트 통과: 면적·공간 겹침·외곽 경계·음수/비정상 숫자·회전·중복·관찰 근거·문 개구부·dangling 참조, 업로드 검증, OpenAI SDK 요청/모의 성공/거절 응답, 프록시 환경 동일 출처/외부 출처 요청.

브라우저에서 예시 2D/3D, 실내 시선 회전, 전체 화면과 안내 문구, 모바일 390px 화면 및 사진 누락 오류를 확인했습니다. 실제 HTTP API에서 키 누락 503 및 잘못된 입력 400 응답을 확인했습니다. 추가 테스트에서 근거 없는 화장실·칸막이·가구·연결 제외, 빈 영역 미생성, 방 라벨 중복 방지, 제거된 칸막이 참조 정리를 확인했습니다.

OpenAI 인증과 gpt-4o Responses API 호출 성공은 확인했습니다. 이번 사진 근거 제한 규칙은 모의 응답 및 정규화 테스트로 검증했으며, 사용자 원본 사진을 다시 분석한 결과는 아직 확인하지 않았습니다. 테스트의 OpenAI 성공 응답은 명시적인 모의 응답입니다. 앱 실행 중에는 모의 분석으로 대체하지 않습니다.

## 미구현 / 한계

- 실측 도면, 사진측량, LiDAR, 사진 텍스처 복원, 사진을 이어 붙인 360° 파노라마가 아닙니다. 360° 뷰는 추정 3D 모델의 시선 회전입니다.
- 비직사각형 외곽, 복층, 여러 세대, CAD 내보내기는 미지원입니다.
- 모델이 같은 물체에 서로 다른 identity와 위치를 부여하면 중복 억제가 완벽하지 않을 수 있습니다. 서로 매우 가까운 동일 종류 물체는 하나로 합쳐질 수 있습니다.
- 외곽 경계는 보정하지만 가구 간/칸막이와의 모든 충돌, 문 여닫힘 공간, 실제 통행 가능성의 완전한 최적화는 구현하지 않았습니다.
- 일부 가구 모델은 단순화된 형상입니다. 조명과 재질은 사진에서 복원한 값이 아닙니다.
- 실제 휴대전화의 터치·GPU 및 브라우저별 전체 화면 동작은 별도 기기 검증이 필요합니다.
- 회원가입, 결제, 데이터베이스는 요청 범위에 따라 만들지 않았습니다. 공개 배포는 수행하지 않았습니다.
- 서버리스로 배포할 경우 플랫폼의 요청 크기 제한과 실행 시간을 고려해야 합니다. 현재 앱은 최대 약 57MB 요청/240초 OpenAI 대기를 허용하는 Node 서버 기준입니다.

## 관찰한 구조 보존 규칙

사진에서 보이는 벽·문·창문·가구는 위치나 치수가 불확실해도 추정하여 구현합니다. `evidence.source`는 존재의 관찰 여부이며 좌표가 실측되었다는 뜻이 아닙니다. 보이는 화장실은 별도 사진만 있어도 배치를 추정하되 불확실성을 기록합니다. 사진에 없는 별도 공간이나 물체만 추가하지 않습니다. 관찰된 문·창문은 이를 지지하는 벽의 존재 근거로 사용합니다.

3D는 기본적으로 모든 벽을 표시합니다. 내부가 가려지면 '앞쪽 벽 숨기기' 또는 실내 보기로 전환할 수 있습니다. 문짝·문틀·손잡이를 표시하며 문짝은 추정 방향으로 90도 열린 상태입니다.

현재 사진 분석은 GPT-6 Astra / reasoning low (Light) / 최대 출력 24,000토큰을 사용합니다. 상위 모델 접근은 실제 API로 확인했습니다. 모델 변경 후 사진별 평면도 정확도 비교 평가는 아직 수행하지 않았습니다. 모델 사양: https://developers.openai.com/api/docs/models/gpt-6-astra

## 속도 조정

GPT-6 Astra의 추론을 low (Light)로 조정하고, 공통 문·창문·가구 기준의 방향 일치와 상대 배치를 지시하도록 프롬프트를 간결하게 정리했습니다. 사진 입력은 high를 유지합니다. 동일한 사진 순서·전용면적·API 키·분석 버전의 결과는 서버 메모리에서 5분간 재사용하며 최대 12개로 제한합니다. 같은 요청의 동시 분석도 합칩니다. 사진과 키 원문은 캐시에 보관하지 않습니다. 사용자는 '결과 재사용 없이 새로 분석'으로 새 추정을 요청할 수 있습니다.

화면에 실제 경과 시간과 서버 처리 시간이 표시됩니다. 최초 분석 속도 및 사진 재구성 정확도의 전후 비교는 아직 측정하지 않았으므로 개선률을 보장하지 않습니다. 회귀 테스트는 데이터 처리 및 캐시의 작동 검증입니다.

전체 외곽의 추정 면적은 입력 전용면적의 80~100%를 허용합니다. 범위 안의 추정은 유지하고 범위 밖만 가장 가까운 경계로 보정합니다. 결과에 입력 면적과 추정 면적을 구분해서 표시합니다.

평면도는 floorPlan 필드로 최대 1장 선택이며 JPG/PNG/WebP, 최대 8MB입니다(PDF 미지원). API 입력 이미지 순서는 평면도=1, 실내 사진=2~7입니다. 평면도를 구조의 우선 근거로 사용하고 사진은 가구 배치를 보완합니다. 평면도에서만 확인되는 구조도 observed로 보존합니다. 새 평면도 입력을 포함해 캐시 키를 계산합니다. 실제 사용자 평면도와 사진의 정확도 평가는 아직 수행하지 않았습니다.

평면도 없이도 실내 사진 1~6장과 면적으로 분석할 수 있습니다. 평면도 유무를 모델과 캐시에 명시하며, 없으면 이미지 1부터 모두 실내 사진입니다. 테스트 28개 통과.

평면도 1장만으로도 분석할 수 있습니다. 평면도가 없을 때만 실내 사진 1~6장을 요구하며 둘 다 없으면 거부합니다. 평면도만 입력하면 확인되지 않은 가구는 추가하지 않습니다.

문은 벽의 개구부와 문틀만 표시합니다. 3D 문짝·손잡이와 2D 문 열림 호는 표시하지 않습니다.

## Viewliet 복층 첫 버전
부분 직사각형 복층 1개, 직선 계단, 상부 난간과 복층 가구를 지원합니다. `loft=null`은 단층입니다. 복층의 `furnitureIds`가 위층 가구를 지정하며 좌표는 공통 x/z, 바닥 높이는 `elevation`입니다. 계단은 복층 가장자리에서 외측으로 이어집니다. 아래층/복층 평면도 전환 및 3D 시점 이동을 지원합니다. 사진이 없어도 '복층 예시 체험'으로 확인할 수 있습니다.
입력 면적은 아래층 외곽 기준(80~100%)이며 복층 면적은 별도 표시합니다. 사진·도면에서 복층이 관찰될 때만 생성합니다. 복층의 절대 높이와 계단/난간은 추정이며 실제 시공 규격이 아닙니다. 계단과 모든 기존 가구·칸막이 사이의 자동 충돌 해소, L자 계단, 여러 복층, 비직사각형 바닥은 아직 지원하지 않습니다. 실제 복층 사진 정확도는 미평가이며 예시 렌더링과 34개 회귀 테스트로 검증합니다.

## GitHub에 올리기

이 폴더가 저장소 루트입니다. `.env.example`만 공유하고 실제 키가 있는 `.env.local`은 공유하지 않습니다. 의존성·빌드 결과·로그는 `.gitignore`로 제외합니다.

```sh
git add .
git diff --cached --stat
git commit -m "Initial Viewliet app"
git branch -M main
# GitHub에서 빈 저장소를 만든 후 해당 저장소 주소 사용
git remote add origin https://github.com/YOUR_USERNAME/viewliet.git
git push -u origin main
```
